# 寒窗 1.4.3

这一版只干一件事：**把「检查更新」做进设置里**，并且让它真的能用。

## 新增

- 设置面板新增「关于与更新」页：
  - 显示当前版本；
  - 「检查更新」按钮 → 向 GitHub 查询最新 release；
  - 有新版时显示版本号、安装包名和大小，可「下载安装包」（带百分比进度条），下载完可「运行安装包」直接覆盖安装；
  - 「打开发布页」用系统浏览器打开对应的 release 页面。
- 检查更新走 **GitHub REST API**（`https://api.github.com/repos/haomingtang787-ai/HanChuang/releases/latest`），不抓 `github.com` 网页、不登录、不上传任何本机数据；未登录额度 60 次/小时，正常使用足够。
- 下载安装包同样走 API 的 asset 地址，校验大小，只接受 `HanChuang-setup-*.exe`，下载到本机 `updates` 目录，只允许运行这个目录里的 exe。

## 修复

- **TLS 证书问题**：Node 自带 fetch 在装了杀软或公司根证书的机器上会报 `unable to verify the first certificate`，导致检查更新一直「fetch failed」。现在改用 Electron 的 Chromium 网络栈（系统证书 + 系统代理都能用）。
- 清掉更新链路里残留的旧品牌：仓库默认 `haomingtang787-ai/HanChuang`，安装包正则 `HanChuang-setup-*.exe`，user-agent `hanchuang-app`；需要指向别的仓库可用环境变量 `HANCHUANG_UPDATE_REPO=owner/repo`。

## 更新会不会丢数据

不会。更新只替换程序文件；课程、课件、对话、错题、API Key 都在 `%APPDATA%\desk-teacher-agent\library` 下，安装程序不会动它。
