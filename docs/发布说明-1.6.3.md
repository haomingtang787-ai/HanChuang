# 寒窗 1.6.3 · 价格按官方峰谷价重算

## 问题

界面里的费用一直比 DeepSeek 实际账单低。原因不是四舍五入，而是 `logic.ts` 里硬编码的价目表停留在旧价：

- Flash 输出写成 **2 元/百万 tokens**，官方当前是闲时 **4**、高峰 **8**。
- Pro 写成 3 / 0.025 / 6，官方当前是闲时 4.5 / 0.15 / 13.5，高峰 9 / 0.3 / 27。
- 历史用量按“当前模型、当前价格”一把算，不区分每次调用发生的时间，也不区分闲时/高峰。

所以 42 页 PDF 的备课预估价显示 `¥0.02–0.03`，官方闲时实际约 `¥0.03–0.04`，高峰约 `¥0.06–0.09`；一个 5 万输入、1.5 万输出的课堂，界面约 `¥0.07`，官方闲时约 `¥0.10`。

## 修复

- 新增 `src/shared/pricing.ts`，统一维护 DeepSeek 官方价目表：
  - Flash：闲时 0.02 / 1 / 4，高峰 0.04 / 2 / 8。
  - Pro：闲时 0.15 / 4.5 / 13.5，高峰 0.3 / 9 / 27。
  - 单位均为“元/百万 tokens”，顺序为“缓存命中 / 缓存未命中 / 输出”。
- 按北京时间判断峰谷：周一至周五 9:00–12:00、14:00–18:00 为高峰，其余时段为闲时；法定节假日暂按工作日处理，属于偏高估计。
- 历史用量统计改为逐行读取 `ai_usage`，每次调用按自己的 `model` 和 `created_at` 判断峰谷并计价；同一门课跨模型、跨峰谷不会再被当前价覆盖。
- 备课预估价按当前时段显示，左栏提示“高峰约为闲时的两倍”。
- 本课用量弹层直接显示逐次调用累加出的官方价，不再用当前模型价重算整门课。
